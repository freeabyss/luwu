# ADR 模板

```markdown
# ADR-XXXX: [决策标题]

## 状态
[提议 | 已通过 | 已废弃 | 已替代]

## 背景
[为什么需要做这个决策，我们面临什么问题？]

## 决策
[我们决定采用什么方案。清晰、明确地陈述决策内容。]

## 后果
### 正面影响
- [好处1]
- [好处2]

### 负面影响
- [坏处1]
- [坏处2]

## 备选方案
### 方案A：[方案名称]
- 优点：...
- 缺点：...

### 方案B：[方案名称]
- 优点：...
- 缺点：...

## 相关决策
- [相关ADR链接]
- [相关文档链接]

---
决策日期：YYYY-MM-DD
决策人：[姓名]
```

## ADR 编号规则

- 按序号递增：0001, 0002, 0003...
- 不要复用已废弃的编号
- 废弃的ADR保留文件，将状态标记为"已废弃"
- 如果一个ADR替代另一个，在新ADR中说明替代关系

## 何时创建ADR

必须创建ADR的场景：
1. 技术栈选型（数据库、框架、语言等）
2. 架构风格决策（微服务、单体、事件驱动等）
3. 难以逆转的设计决策
4. 可能让后人困惑的"奇怪"设计
5. 存在明显取舍的权衡决策

不需要创建ADR的场景：
1. 编码风格（放入代码规范文档）
2. 局部实现细节
3. 明显且无争议的选择
