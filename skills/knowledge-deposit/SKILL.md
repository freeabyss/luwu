# 知识沉淀 Skill

## 核心能力

自动扫描 `inputs/` 目录下的新增内容，分析并提炼为结构化知识，自动沉淀到知识库对应目录。

## 触发条件

1. **手动触发**：运行 `/knowledge-deposit`
2. **定时触发**：每日凌晨自动扫描增量内容
3. **对话触发**：当对话中产生有价值的架构决策、工程规范、经验教训时

## 知识分类与目标目录

| 知识类型 | 识别关键词 | 目标目录 |
|----------|-----------|---------|
| **架构决策** | 选型、架构模式、技术栈、ADR、决策 | `core/decisions/` |
| **架构模式** | 分层、DDD、微服务、设计模式、设计原则 | `core/architecture/` |
| **工程规范** | 编码规范、测试规范、CR 规范、流程规范 | `core/engineering/` |
| **业务知识** | 业务流程、行业术语、业务规则 | `business/` |
| **领域知识包** | 领域模型、ER 图、API 契约 | `packs/` |
| **经验教训** | Bug、故障、复盘、踩坑、教训 | `lessons/` |
| **Skill 优化** | 流程改进、Prompt 优化、自动化 | `skills/` |

## 标准工作流

### Step 1: 扫描与检测
```bash
# 检测 inputs 目录下 24 小时内新增/修改的文件
find inputs/ -mtime -1 -type f -name "*.md"
```

### Step 2: 内容分析

对每个文件，让 AI 回答以下问题：
1. 这篇文章的核心观点是什么？（3-5 条）
2. 属于哪类知识？（参考上面的分类）
3. 有哪些可以落地为规范的原则？
4. 有哪些经验教训或反模式？
5. 是否可以直接生成对应的 ADR/规范文档？

### Step 3: 知识提炼模板

#### ADR 文档结构（`core/decisions/`）
```markdown
# ADR-[编号]: [决策标题]
- 状态: 已接受
- 日期: [YYYY-MM-DD]

## 1. 背景
## 2. 决策
## 3. 原因
## 4. 影响
```

#### 架构规范文档结构（`core/architecture/`）
```markdown
# [架构模式名称] 落地规范
- 适用场景: [...]
- 更新日期: [YYYY-MM-DD]

## 1. 核心原则
## 2. 强制规范
## 3. 标准代码示例
## 4. 常见反模式
```

#### 工程规范文档结构（`core/engineering/`）
```markdown
# [规范名称]
- 适用场景: [...]
- 更新日期: [YYYY-MM-DD]

## 1. 核心原则
## 2. 强制规范/流程
## 3. 标准模板/示例
## 4. 常见反模式
```

#### 经验教训文档结构（`lessons/`）
```markdown
# [复盘标题]
- 发生日期: [YYYY-MM-DD]
- 影响范围: [...]

## 1. 现象描述
## 2. 排查过程
## 3. 根本原因
## 4. 解决方案与防御机制
```

### Step 4: 质量检查

沉淀前必须检查：
1. ✅ 文档结构是否符合对应目录的模板要求
2. ✅ 内容是否有具体可落地的原则，而不是空泛的概念
3. ✅ 是否提炼了可执行的规范/红线，而不只是描述现象
4. ✅ 是否包含反模式或避坑指南
5. ✅ 文件名是否清晰有意义

### Step 5: 索引更新

沉淀后更新 `MEMORY.md`，添加新文档的索引条目。

### Step 6: 已沉淀文件归档

成功沉淀后，将已处理的源文件归档到 `inputs/_归档/` 目录下：

```bash
# 创建归档目录（按年月分类）
mkdir -p inputs/_归档/$(date +%Y-%m)/

# 移动已处理文件
mv inputs/已处理的文件.md inputs/_归档/$(date +%Y-%m)/
```

**归档规则**：
- ✅ 完全沉淀且质量等级为 A 的文件 → 自动归档
- ⚠️ 质量等级为 B 且生成了草稿的文件 → 保留在 inputs，标记 `[待补充]` 前缀
- ❌ 未沉淀或被跳过的文件 → 保留在 inputs，标记 `[分析中]` 或 `[资料]` 前缀
- 📅 归档目录按年月组织：`inputs/_归档/2026-06/`

### Step 7: 自动提交并推送到 GitHub

所有沉淀操作完成后，自动提交变更并推送到远程仓库：

```bash
# 添加所有变更
git add .

# 生成提交信息（包含沉淀的文件列表）
git commit -m "docs: 知识沉淀 [$(date +%Y-%m-%d)]

- 新增: core/decisions/xxx.md
- 新增: core/engineering/xxx.md
- 归档: inputs/_归档/$(date +%Y-%m)/xxx.md"

# 推送到远程仓库
git push
```

**提交规范**：
- 提交信息前缀统一使用 `docs: 知识沉淀 [YYYY-MM-DD]`
- 提交内容列出新增/修改的文档路径
- 如无新增文档（仅调整或归档），使用 `docs: 知识库维护 [YYYY-MM-DD]`

## 执行命令

```bash
# 全量扫描并沉淀
/knowledge-deposit --all

# 只扫描最近 24 小时增量
/knowledge-deposit --incremental

# 指定单个文件沉淀
/knowledge-deposit --file inputs/xxx.md

# 模拟运行，只分析不实际写入
/knowledge-deposit --dry-run
```

## 质量控制标准

| 质量等级 | 沉淀标准 | 处理方式 |
|----------|---------|---------|
| **A 级** | 有明确原则、有强制规范、有反模式 | 自动沉淀 |
| **B 级** | 观点明确，但缺少具体落地细节 | 生成草稿 + 提示人工补充 |
| **C 级** | 只有概念描述，没有可落地内容 | 跳过 + 提示继续积累更多材料 |
