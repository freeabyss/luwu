# 设计：PRD 技能联动 ui-ux-pro-max

**日期**：2026-07-26
**状态**：已批准
**范围**：全局 `/prd` 技能（影响所有项目）

---

## 背景

用户期望：在执行 `/prd` 时，只要任务涉及前端页面、视觉样式、布局、配色、组件规范或交互设计等设计决策，PRD 流程应调用 `ui-ux-pro-max:ui-ux-pro-max` 技能，并将其设计结论写入 PRD，而不是由 PRD 技能自行泛化设计。

当前 `~/.claude/skills/prd/SKILL.md` 仅在文档层面要求"若涉及界面，必须描述页面交互"，不调用任何外部设计技能，也没有独立的 UI/UX 输出章节。

## 决策

采用**方案 A：SKILL.md 指令注入**——在全局 PRD 技能的 `SKILL.md` 和 `PRD_TEMPLATES.md` 中加入明确的触发判断、调用步骤、输出章节和检查项。不修改第三方插件，不引入 hooks/commands/agents 等额外机制。

## 触发条件

当且仅当需求满足以下任一条件时触发 UI/UX 调用：

- 新增页面或视图
- 对已有页面进行视觉改版
- 需要确定布局系统、视觉风格、配色、字体
- 需要确定组件规范或交互模式
- 需要确定响应式策略或可访问性要求

不触发场景：

- 纯后端逻辑、API/数据库设计
- 仅记录既有页面的小改动（如文案修改、字段增减）
- 基础设施、DevOps、脚本自动化
- 非可视任务

## 调用时机

功能需求澄清完毕后、生成 PRD 正文前。顺序：

```
步骤 1：澄清问题（含 UI/UX 判定）
步骤 2：维护已有 PRD 规则
步骤 3：生成 PRD 总体要求
步骤 3.5：UI/UX 设计规范（条件触发）   ← 新增
PRD 模板
...
```

设计服务于功能，避免 UI 先入为主导致反复。

## 调用方式与输入输出

使用 `Skill` 工具调用 `ui-ux-pro-max`，传入：

- 产品/功能类型
- 目标用户与使用场景
- 设计决策点清单
- 目标技术栈（Vue/Ant Design Vue、uni-app、React 等）

将返回结论提炼为 7 个结构化维度：

1. 风格定位（Style）
2. 色板（Color Palette，含语义色 token）
3. 字体与排版（Typography）
4. 间距与布局系统（Spacing & Layout）
5. 关键组件规范（Key Components）
6. 交互模式与动效（Interaction & Motion）
7. 响应式/可访问性要求（Responsive & Accessibility）

## PRD 输出位置

在 PRD 统一模板中新增独立章节「UI/UX 设计规范」，位于「非功能需求」之后、「验收标准」之前。功能需求章节中的页面交互表格只引用该章节，不重复设计规范内容。

## 失败处理

若 `ui-ux-pro-max` 调用失败或返回结论不明确：

- PRD 继续输出其他章节（不阻塞）
- 在「待解决问题」中标注「UI/UX 设计规范未完成」
- 列出具体待决项
- 保存前检查清单中记录此状态

## 改动文件

| 文件 | 改动内容 |
|------|----------|
| `~/.claude/skills/prd/SKILL.md` | 步骤 1 末尾增加 UI/UX 判定项；新增步骤 3.5；保存前检查清单增加两项 |
| `~/.claude/skills/prd/PRD_TEMPLATES.md` | 统一模板中新增「UI/UX 设计规范」章节表格 |

## 不改动

- 不修改 ui-ux-pro-max 插件文件（第三方，升级会覆盖）
- 不修改 `settings.json`
- 不新增 hooks/commands/agents/workflows
- 不改变纯后端/纯 API 类 PRD 的现有行为
